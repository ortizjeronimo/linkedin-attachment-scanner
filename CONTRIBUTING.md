# Contributing

Thanks for helping improve LinkedIn Attachment Scanner. Bug reports, new detection rules and fixes for LinkedIn markup changes are all welcome.

## Getting set up

The extension is plain JavaScript with no build step and no third-party dependencies. Everything Firefox loads is in `src/`.

1. Clone the repository.
2. Open `about:debugging#/runtime/this-firefox` in Firefox 140 or newer.
3. Click **Load Temporary Add-on…** and pick `src/manifest.json`.
4. After changing code, click **Reload** next to the extension, then reload the LinkedIn tab.

With Node.js installed you can also use `npx web-ext run --source-dir src`, which reloads on every change.

## Before you open a pull request

- Run `npx web-ext lint --source-dir src` and fix anything it reports. CI runs the same check and treats warnings as errors.
- Run `node test/analyzer.test.js`. If you change a detection rule, add a crafted file to that test with the verdict it should get.
- Test the change in Firefox against a real LinkedIn conversation with an attachment. The browser-side code has no automated tests.
- Keep the code dependency-free. If a change really needs a third-party library, say why in the pull request and regenerate the SBOM (below).
- Build UI with `textContent` and DOM APIs, never `innerHTML`. Filenames and file contents are attacker-controlled.
- Don't commit API keys, OAuth client IDs or other credentials. Keys belong in the extension's settings, which are stored in the browser.
- If you add a permission to `manifest.json`, explain what needs it.

## Security scans

These run in Docker, so nothing needs installing besides Docker itself. Run them from the repository root. In PowerShell use `${PWD}`; in bash use `$(pwd)`.

Secrets, with [Gitleaks](https://github.com/gitleaks/gitleaks):

```
docker run --rm -v "${PWD}:/src" ghcr.io/gitleaks/gitleaks:latest dir /src --redact --verbose
```

Vulnerable dependencies, secrets, misconfigurations and licences, with [Trivy](https://trivy.dev/):

```
docker run --rm -v "${PWD}:/src" -w /src aquasec/trivy:latest fs --scanners vuln,secret,misconfig,license .
```

Both should finish with no findings. The `security.yml` workflow runs the same two tools (pinned to fixed versions) plus CodeQL on every push and pull request.

## SBOM

`sbom.cdx.json` is a CycloneDX software bill of materials generated by Trivy. Its component list is empty because the extension has no third-party dependencies. Regenerate it whenever a dependency is added or the version in `src/manifest.json` changes:

```
docker run --rm -v "${PWD}:/src" -w /src aquasec/trivy:latest fs --format cyclonedx --output sbom.cdx.json .
```

Trivy names the top-level component `.`; after regenerating, set `metadata.component.name` back to `linkedin-attachment-scanner` and `version` to the manifest version.

For an ordinary version bump there is nothing to regenerate: `scripts/set-version.sh <version>` updates the manifest and the SBOM together, and CI fails if the two versions differ.

## Reporting a vulnerability

If you find a way to make the scanner report a dangerous file as clean, or a security problem in the extension itself, please report it privately through the repository's **Security → Report a vulnerability** page instead of opening a public issue.
